# Final integrated HP sampling source review

The integrated engine changes have no unresolved material source defect identified by this review. I reread the complete three-file diff against frozen cc54 after archiving the quality pair, then checked the three current file hashes against the tested V3 binding. All three match exactly. The final source changes are integrated through commit 78d2dc9; the original isolated commit identifiers in raw build proofs describe the same file bytes.

The V1 invalid-enum failure is repaired with complete CUDA_MEMCPY3D and CUDA_MEMCPY3D_PEER literals. Both memory-type fields use DEVICE; pointers, contexts, pitches, offsets, dimensions and unused fields are explicitly initialized. The CPU constructor test exercises these Rust descriptors without CUDA, including the final vocabulary slice. The V2 fragmented-log failure is repaired by formatting the complete label, JSON and newline before acquiring stderr and invoking write_all. Both audit sites use this helper, and write errors propagate through audit-only paths. These fixes preserve the recorded failures rather than weakening their gates.

The collection path synchronizes each source GPU before the shared host barrier. GPU0 then enqueues one local and seven peer copies on its own stream, followed by the unchanged sampler and result download. The engine collects all eight worker results before accepting another command, so an early return by a nonzero worker cannot permit source-buffer reuse. Reported worker errors terminate the process instead of joining workers blocked at the readiness barrier. The audit first checks every collected logit bit against independently downloaded slices, then replays the same sampler tables and uniforms after production sampling has completed. Its overwrite is confined to GPU0's existing full-sized workspace.

The explicit opt-in requires eight GPUs, a supported split vocabulary head and suitable vocabulary divisibility. Table validation bounds the available rows, draft counts, token IDs and uniforms before GPU use. Default HP dispatch remains on the CPU. Top-p and hesitation fallbacks and pure greedy dispatch remain present; the archived strict actual audit records their coverage. The DP path retains the previously tested prefill eligibility change. No kernel source or quantized weight change is part of this patch.

## Remaining evidence limits

The teacher evaluator uses generic Engine::step, which is unchanged by this patch. Its three passing V3 results therefore supplement the actual StepSampleHp collection/replay audit; they do not replace it. Replaying the existing kernel proves agreement for the supplied real logits and tables, rather than independently proving the sampler's probability distribution for every possible input. Changing the path also changes random-number consumption relative to early rejection on the CPU, so equal seeds do not guarantee identical generated text or pass counts across CPU and GPU timing arms.

The original near-boundary quality result remains retained alongside both paired results. The available measurements do not establish the cause of quality variation, an allocation effect, or a distributional bound on future runs. Memory observations are polled and cannot exclude a shorter transient minimum. The paired processes released their allocations successfully, but fresh production HP4/256K capacity and Pi validation were still owned by the parent when this review was written. The archived promotion marker explicitly preserves that scope. This review performed no build, GPU inference or model transition.
